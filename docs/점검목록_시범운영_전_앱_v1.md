# 시범 운영(3~5명) 전 앱 점검 목록 v1

작성: 2026-11-06 [KIRO] · 대상 앱: 1.6.8(versionCode 20) → 1.6.9(점검용)
목적: 11-06 대표 폰에서 "다른 앱 위에 표시" 권한이 설정은 허용인데 실제로는 거부(dumpsys `granted=false`)가 되어 수신 팝업·메모 버블이 모두 막힌 일이, **일반 업데이트**로도 생기는지 확인한다. 원인은 아직 확정되지 않았다(12:56 첫 실패 / 11:20쯤 1.6.4 설치·서명 교체 / 12:56:15 구글 플레이 서비스 업데이트).

## 준비
- [ ] 보조 삼성폰 1대 (대표 폰이 아닌 것, Android 14 이상, 삼성 전화 또는 T전화)
- [ ] 이 폰에 리드마스터를 한 번도 설치한 적 없으면 가장 좋음. 있으면 **앱 삭제 후** 시작
- [ ] 시험용 리드 1건 (번호를 아는 다른 폰, 예: 김김김 010-****-4901)
- [ ] PC 연결(adb)은 **확인용으로만** 사용한다. 권한을 adb로 고치지 않는다 (고치면 시험이 무의미해짐)

## 1단계: 새로 설치 (1.6.8)
- [ ] 웹 `…/leadmaster-crm/app/LeadMaster.apk`를 폰 브라우저로 받아 설치 (상담원과 같은 방법)
- [ ] 구글 로그인 → 앱 세션 전달 확인 (앱 상태표시줄 "로그인 필요"가 사라짐)
- [ ] 권한 점검 화면에서 필수 항목 전부 허용: 전화·통화기록·문자, 다른 앱 위에 표시, 발신자 정보 앱(LeadMaster), 알림
- [ ] 권한 점검 화면에 "동기화 필요" 같은 경고가 **뜨지 않는다** (정상 폰 오탐 확인)
- [ ] 확인 기록(adb): `dumpsys package com.leadmaster.app | grep SYSTEM_ALERT_WINDOW`, `appops get com.leadmaster.app SYSTEM_ALERT_WINDOW`, `cmd role get-role-holders android.app.role.CALL_SCREENING` 결과를 그대로 적어 둔다 (정상 폰의 기준값)

## 2단계: 1.6.8 동작
- [ ] 리드 번호로 수신 → 울리는 동안 카드 팝업 (popup_debug.log에 "수신팝업 num=" 다음 줄에 "대신 알림"이 **없음**)
- [ ] 받으면 메모 버블 표시 (logcat에 `FloatingButtonService: No overlay permission` **없음**)
- [ ] 메모 저장 → 웹 상담 이력에 들어감
- [ ] 리드가 아닌 번호로 수신 → 번호는 받지만 팝업 없음(정상, 지금 앱은 리드만 팝업). popup_debug에 "수신번호=" 기록 확인
- [ ] 녹음: 보조 폰 전화 앱의 통화 자동 녹음이 켜져 있어야 업로드 시험 가능 (11-06 보조 폰은 녹음 파일 0개)
- [ ] PC에서 전화 걸기 → 폰이 발신, 통화중 버튼에 고객 이름
- [ ] PC에서 문자 보내기 → 폰이 발송
- [ ] 통화 끝 10초 안에 통화기록 업로드, 녹음 드라이브 보관·AI 정리(회사 설정 켜져 있을 때)
- [ ] 간편 콜 모드: 메뉴 "간편모드" → 통화 → 결과 입력 화면 복귀

## 3단계: 일반 업데이트 (1.6.8 → 1.6.9)
- [ ] 1.6.9 = 기능 변경 없이 versionCode 21만 올린 빌드, 같은 디버그 키(66b2246b…)로 서명. 서명 키·applicationId를 바꾸지 않는다
- [ ] 웹에 게시(public/app/LeadMaster.apk + version.json versionCode 21) — 대표님 승인 후
- [ ] 보조 폰: 앱 메뉴 **[앱 업데이트 확인]** → 설치 (PC 사용 안 함)
- [ ] 업데이트 직후 1단계의 adb 확인 3가지를 다시 적고, **설치 전과 비교** (특히 `granted=`, Uid mode, CALL_SCREENING 역할)
- [ ] 2단계 수신 시험 다시: 팝업·버블이 뜨는가
- [ ] 폰 재부팅 후 수신 시험 한 번 더 (BootReceiver로 감시 서비스가 다시 뜨는지)

## 결과 판정
- 3단계 뒤에도 팝업·버블 정상 → 일반 업데이트는 안전. 11-06 대표 폰 건은 서명 교체·다운그레이드 등 개발 중 설치 탓으로 정리
- 3단계 뒤 막힘(`granted=false` 등) → 상담원 배포 보류. 원인(업데이트 방식/역할 재부여)을 찾고, 폰만으로 복구하는 방법(발신자 정보 앱 다시 지정, 앱 재설치 등)을 실제로 시험해 안내서에 넣는다

## 배포 규칙 (이번 일로 정함)
- 같은 versionCode로 다시 빌드해 게시하지 않는다 (이미 받은 폰은 고친 판을 못 받음). 고치면 항상 +1
- 개발 PC에서 `adb install -d`(다운그레이드)·서명 바꾼 빌드 설치는 대표 폰에서 하지 않는다. 필요하면 보조 폰에서
- adb로 권한을 고쳤으면 인계 일지에 반드시 적는다 (상담원 폰에는 adb가 없으므로 같은 상황 재현이 안 됨)
