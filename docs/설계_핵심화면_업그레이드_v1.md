# 리드마스터 핵심 화면 업그레이드 v1 (2026-11-01)

대상: 케이스 목록(`/cases`), 신규 등록(`/new`), 리드 상세(`/case/:id`), 정산(`/settlement`), 통화 녹음 AI 정리의 거래처 설정 연동.
목표: 상담원이 리드를 빨리 찾고, 접수 → 통화 → 정보 수집 → 사무실 전달을 한 흐름으로 끝내고, 대표가 사무실별로 받을 돈을 정확히 관리한다.

## 1. 조사에서 찾은 문제 (코드 근거)

### 케이스 목록
- 한 쪽 10건 고정 → 1,463건이면 147쪽. 쪽 크기를 바꿀 수 없었다.
- 칸반이 **현재 쪽 10건만** 보여 줬다. 칸반에서 상태를 옮기면 이탈 사유·상태 기록 없이 바뀌었다.
- 담당자(배정) 필터·표시가 없었다. 여러 건을 골라 상태 변경·배정·삭제할 방법이 없었다.
- 지난(처리 안 한) 일정은 목록에서 아예 안 보였다(다음 예정만 표시).
- 글자를 칠 때마다 1,463건의 메모 전체를 바로 검색했다. 상태 이력 툴팁은 열 때마다 전체 리드를 복사했다. 행마다 순차 애니메이션.
- 목록에서 상태를 바꾸면 상태 변경 기록이 남지 않았고 토스트가 두 번 떴다.

### 신규 등록
- 1,610줄 파일에 같은 폼이 모바일·PC용 두 벌, 상세 화면까지 세 벌.
- 이름·번호 필수 검사가 없었다(빈 이름은 '이름없음', 번호 '010'만 있어도 저장). 중복 번호는 경고만 하고 기존 리드로 갈 방법이 없었다.
- 신규 리드를 열면 등록 화면(`/new?leadId=`)으로 가서, 메모를 쓰면 **기존 메모 배열을 새 1건으로 덮어쓸 수 있었다**. 저장하면 상태 목록에 없는 '상담진행'이 들어갔다.
- "Ctrl+Enter 즉시 등록" 안내만 있고 동작하지 않았다.

### 리드 상세
- 정보 탭이 모바일·PC 화면을 **둘 다 그려 두고 CSS로 숨겨** 모든 칸이 두 번 렌더됐다.
- 칸 하나 저장할 때마다 목록 전체 쿼리를 무효화했다(낙관적 반영 없음). "실시간 자동 저장" 표시는 실제 저장 상태와 무관한 고정 글자였다.
- 출생년도 "77" → "1977" 변환이 한 번 늦게 일어났다(저장 전 옛 값으로 변환).
- 모바일에서 숫자·전화 키패드가 뜨지 않았다. 채무 총액이 화면에 없었고, 입력한 채무는 고칠 수 없었다(삭제 후 다시 입력).
- 거래처의 "입력 항목 설정"은 신규 등록 화면에서만 쓰였다. 상태 변경 기록의 작성자는 늘 'User'.
- 사무실에 보내는 요약문에 자동으로 생기는 "[2차 상태 변경]" 메모가 섞였다. 요약문 양식 안내의 치환자 일부(`{{jobType}}`, `{{incomeNet}}`, `{{creditLoan}}`)는 실제로 치환되지 않았다.

### 정산
- **주간 배치 수수료 중복**: 1차·2차 입금이 다른 주에 있으면 누적 지급액을 주마다 더해 50% + 100% = 150%가 잡힐 수 있었다.
- 같은 계산이 4곳 이상에 서로 다르게 구현돼 있었다(계약금 기준을 구간 최저 수임료로 볼지 수임료로 볼지, 100% 기준이 0일 때 처리, 규칙 고르는 순서).
- "받은 수수료"는 실제로 받은 돈이 아니라 고객 입금으로 **추정**한 값이었다. 사무실이 리드마스터에 줘야 할 **미수금은 어디에서도 계산하지 않았다**("장기 미수금"은 고객 → 사무실 미납).
- 오늘 날짜를 UTC로 구해 한국 시간 오전 9시 전엔 어제가 됐다. 분납 KPI가 항상 0, '고객취소'가 장기 미수금에서 빠지지 않음, 수금 버튼을 두 번 누르면 페이백 지출 중복.

### 통화 녹음 AI 정리
- 요약 규칙(AI 요약 프롬프트)만 거래처 설정을 썼다. 사무실 요약문 양식·필요 항목·분류 기준은 연결되지 않았다.

## 2. 이번에 바꾼 것

### 공통 디자인
- 본문 글꼴 Pretendard(화면에 쓰는 글자만 내려받음), 배경 `#F4F5F7`, 본문 `slate-900`. 숫자는 `tabular-nums`로 자리 맞춤.
- 색은 **정보에만** 쓴다: 상태 색은 상세 작업대 왼쪽 띠, 경고(빨강·주황), 완료(초록). 섹션마다 다르던 무지개 헤더를 없애고 같은 흰 카드 + 얇은 테두리로 통일.
- 키보드 포커스 표시(`:focus-visible`), 다크 모드 빠진 곳 보완, 상태 변경 창 폭 360px 화면 대응.

### 케이스 목록
- **빠른 보기**: 전체 · 오늘 할 일(오늘까지 잡힌 처리 안 한 일정 + 신규 + 다시 걸 부재) · 내 담당 · 미배정(관리자). 숫자 표시.
- 담당자 필터와 행마다 "담당 ○○ / 미배정"(관리자, 멤버가 2명 이상일 때).
- **여러 건 선택**(PC): 상태 바꾸기(이탈 사유가 필요한 고객취소·진행불가 제외), 담당 배정·풀기(관리자), 엑셀, 휴지통.
- "지난 일정 MM-DD HH:mm" 빨간 표시. 쪽 크기 20/50/100, "전체 N건 중 1–20" 한국어 표시.
- 칸반은 필터 결과 전체(칸마다 80건까지 그리고 나머지는 숫자). 칸반·목록에서 상태를 바꿔도 이탈 사유 창·상태 기록을 거친다.
- 검색은 한 박자 늦게 반영(useDeferredValue), 번호 일부(숫자 4자리 이상) 검색, 상태 이력 툴팁은 이미 가진 정보로, 문자 발신 여부 조회는 보이는 번호가 바뀔 때만.
- 신규 리드를 누르면 등록 화면이 아니라 **상세(상담 화면)**로 바로 간다.

### 신규 등록 (`/new` 새 화면, 예전 화면은 `/new/full`)
- 순서: **연락처 → 이름 → 받는 사무실 → 유입 경로 → 사건 유형** (+ 접어 둔 사전 정보·첫 메모).
- 번호·이름 필수 검사. 중복이면 "그 리드 열기" 버튼, "그래도 새로 등록"을 체크해야 저장.
- [등록하고 상담 시작](Ctrl+Enter) → 상세로, [등록하고 다음 리드] → 같은 사무실·유입경로로 바로 다음 입력. 마지막 선택을 기억.
- `/new?leadId=…`는 상세로 보낸다(메모 덮어쓰기·'상담진행' 문제 제거).

### 리드 상세 = 상담 화면
- 맨 위 **통화 작업대**(스크롤해도 붙어 있음): 이름·번호(누르면 전화)·사건 유형·사무실·유입경로, [전화] [문자](PC는 바로 써서 앱으로 발송, Ctrl+Enter) [부재 +1] [다음 통화](1시간 뒤·오늘 저녁 6시·내일 오전 10시·모레) [사무실 전달], 1·2·3차 상태, **필수 확인 n/m**, **저장 중 / 저장됨 HH:mm / 저장 안 됨**.
- 신규 리드: "새로 들어온 리드" 안내 + [상담 시작]. 전화·문자를 누르면 자동으로 신규 표시 해제 + '신규접수' → '상담중'(상태 목록에 있을 때) + 기록.
- 정보 탭: **상담 순서대로 한 줄**(접수·인적 → 직업·소득·가족 → 주거 → 채무·재산 → 이력). 위에 거래처 필수 확인 진행률과 단계 바로가기(남은 항목 수). 상담 메모·일정은 오른쪽 고정(모바일은 위). 한 번만 렌더.
- 채무·재산: **총 채무 / 신용(카드 포함) / 담보 / 월 상환(소득 대비 %)** 요약, 입력한 채무를 그 자리에서 고침, 금액 칸 쉼표·숫자 키패드·"1억 2,000만원" 읽어 주기.
- 저장: 화면에 바로 반영하고 실패하면 되돌림, 목록은 그 리드만 고침(전체 재조회 안 함). 상태 기록 작성자 = 로그인한 사람 이름.
- 탭 순서: 상담 정보 · 통화 녹음·AI · 요약문 · 통화·문자 기록 · 타임라인 · 수임료/정산.
- 사무실 전달 창: 보낼 글을 "입력한 정보로 / 통화 녹음 AI 정리 / 예전 AI 요약" 중 고름, 사무실 필수 확인 항목 중 빠진 것 표시(보내기는 막지 않음).

### 거래처 설정 (설정 → 거래처)
- **필수 확인 항목**(17개 중 선택, 기본 12개)과 **분류 기준**(자유 글) 추가. 상담 화면 진행률·AI 정리·전달 창이 같이 쓴다.
- **청구 방식**: 수수료 부가세(별도 +10% / 포함 / 없음), 연체 판단 여유 일수.
- 요약문 양식 치환자 안내를 실제 키로 고치고 `{{debtTotalStr}}`(총 채무) 추가. 예전 이름(`{{jobType}}`, `{{incomeNet}}`, `{{creditLoan}}`)도 치환되게 함.

### 통화 녹음 AI 정리 ↔ 거래처 설정
- 서버 함수가 리드의 거래처 설정을 읽어: 요약 규칙(AI 요약 프롬프트), **사무실 보고서**(요약문 양식의 줄 순서 그대로, 못 들은 칸은 "확인 필요"), **빠진 확인 항목**, **분류**(분류 기준대로 + 이유), 추천 절차.
- 상세 → 통화 녹음·AI: 분류 배지, "다음 통화에서 확인할 것", 사무실 보고서(복사·전달), 상담 정보에 반영(사건 유형 포함).

### 정산 → **받을 돈** (첫 탭)
- 계산을 `utils/settlement.ts` 한 곳으로: 수임료 구간 규칙 → 1단계(구간 최저 수임료 × 계약금 비율 입금, 선지급 비율) / 2단계(100% 기준 금액, 0이면 수임료 전액 입금) → 지급 사유가 생긴 날 → **받을 날**(마감 요일 다음 지급 요일 + 지연 주) → 부가세 반영 청구액.
- 사무실별: 청구할 금액 · 받은 돈 · **남은 돈** · 연체 · 다음 받을 날. 전체: 아직 못 받은 돈, 받기로 한 날 지남, 7일 안에 받을 돈, 이번 달 새 청구, 입금 예정으로 생길 돈.
- **받은 돈 기록**(날짜·금액·메모, 통장 내역에서 가져오기·중복 방지) → 받기로 한 날이 빠른 청구부터 차감. 줄마다 받음/일부/연체 n일/받을 예정.
- **월 정산서**: 그 달 생긴 지급 건 목록 + 공급가·부가세·합계 + 지난달까지 미입금 + 계좌 → 글 복사, 엑셀(줄별).
- 확인 필요: 수당 룰 없음, 고객취소·진행불가인데 수수료가 계산된 건(환불·환수 확인).
- 받은 돈 기록 저장: `settings` 키 `partnerCollections`(회사별 RLS, 저장 전 서버 최신 값과 합침).
- 리드 상세 → 수임료/정산에 같은 계산의 "받을 수수료" 단계 표시. 고객 입금 칸은 칸을 벗어날 때 저장(예전엔 글자마다 저장).
- 고친 버그: 한국 날짜, 분납 KPI, 장기 미수금의 취소 상태, 페이백 중복, 매 렌더 디버그 로그.
- 점검: `npx tsx scripts/settlement_check.ts` (받을 날 계산·단계·부가세·FIFO 차감·연체·정산서 합계 16항목).
