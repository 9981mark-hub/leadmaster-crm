## 4. 작업 방법

### 진행 규칙 (대표님 지정)
- 묻지 않고: 스테이징 DB, 내 PC 테스트, 문서, 로컬 커밋
- 하고 나서 보고: 웹 수정 → `tsc`·`vite build` 통과 → push → 배포
- 먼저 확인: 운영 DB 변경, 고객사 회사 생성, 앱 배포, 비용, 되돌리기 어려운 작업

### 작업용 스크립트
- 실행 위치: `%TEMP%\lm-sqltest` (node + `pg` 모듈이 여기 설치돼 있음). TEMP는 지워질 수 있으므로 **사본 `D:\LeadMaster_Backup\lm-sqltest_scripts`** (없어졌으면 그 폴더를 `%TEMP%\lm-sqltest`로 복사하고 `npm i pg`).
- 비밀값은 모두 `.env.local`에서 읽고 출력하지 않는다.

### 이 PC에서 자주 겪는 문제
- `execute_pwsh`가 첫 글자를 빠뜨리거나 멈춤 → 오래 걸리는 일은 백그라운드 실행 + 결과 파일 읽기.
- `.ps1`에 한글 글자를 넣으면 깨짐 → 웹 폴더는 cwd로 넘긴다.
- `D:\*\01_03-leadmaster-crm`은 백업 폴더(`D:\다운로드_전체백업`)도 잡힌다 → 백업 폴더는 읽기 전용, 건드리지 않음.
- 이 PC에서 `vercel build`는 `spawn cmd.exe ENOENT`로 실패 → `vc_prebuild.mjs`가 대신 빌드.
- git push가 가끔 응답 없이 끊김 → `git ls-remote origin refs/heads/main`으로 실제 반영 확인.
- Vercel CLI: 기본 로그인은 마이김변 계정. 리드마스터는 `--global-config %TEMP%\lm-vercel`(새 계정 로그인 정보, TEMP가 지워지면 `vercel login --global-config ...`로 다시 로그인).
